# Usage collection in Medium Latens / Coleta de uso no Medium Latens

English first; a versão em português vem depois.

## English

### What is recorded

Every event is a JSON object with a timestamp, the anonymous installation id and a type. The types the server records today:

| Type | When | Payload |
|---|---|---|
| `turno_inicio` | a prompt is sent | provider, model name, the prompt text |
| `ferramenta` | the assistant calls a tool | tool id, name and input |
| `ferramenta_fim` | a tool returns | tool id, ok flag, short summary |
| `turno_fim` | the turn ends | ok flag, error message if any, elapsed time |
| `rota` | the panel calls a server route | path and method (never the body) |
| `brief_generate`, `brief_markers` | Creative Brief runs | counts and error message if any |

Once per session, a narrative summary of the session is generated by your own AI account, using its cheapest model, and queued like any other event.

### What is never recorded

- **Credentials.** Values in known provider formats (Anthropic, OpenAI, OpenRouter, ElevenLabs and Meta), AWS keys, JWTs, Stripe, Google, npm, GitLab, Slack, DigitalOcean, Hugging Face and GitHub tokens, PEM blocks, webhook URLs, values of sensitive environment variables, and any field whose name looks like a secret are replaced before the event is written. Text is Unicode-normalized first. A randomness heuristic also removes high-entropy values with repeated case alternation and interleaved digits, then redacts high-entropy neighboring fragments. This runs on every nested value. It is not an absolute guarantee: a secret in an unknown, lowercase-only format may pass. See [Known limitations](../SECURITY.md#known-limitations).
- **Media bytes.** Buffers, typed arrays, base64 with media signatures, long base64 runs, hex dumps and numeric sample arrays are replaced by a `[binario removido]` marker. On top of that, every event is capped at 4096 bytes and every text field at 2048 bytes; a media file cannot fit, whatever its encoding. Truncated events say how many bytes were dropped.

These protections have no switch. They are tested in `test/telemetria.test.js` and `test/telemetria-integracao.test.js`.

### The local queue

Events are appended to `telemetria/fila.jsonl` inside your user directory (`~/.medium-latens` on macOS, `%APPDATA%\Medium Latens` on Windows), mode 0600, at most 5000 lines (older lines are pruned). Nothing is written before you accept the terms at install time. You can open the file at any moment.

### Upload

Every five minutes, batches of at most 200 lines or 1 MB are sent by `POST` to the collection address (`https://coleta.torremaster.com/v1/eventos` by default) with three headers: `x-instalacao` (your anonymous UUID), `x-medium-latens-app` (a fixed public identifier of the app, a noise filter and not a secret) and `x-termos` (the version of the terms you accepted). Lines are removed from the queue only after the server confirms the count. On failure the client backs off, doubling up to 30 minutes. If the receiver is offline, the queue simply accumulates and is pruned at 5000 lines; nothing is lost silently, and the status page shows the last result.

### Mandatory, active or off

Official installers write a `BUILD` stamp next to `VERSION`. With that stamp, collection is mandatory and the environment variable is ignored; this is what the terms describe. A checkout of the source has no stamp: collection is active by default and `MEDIUM_LATENS_COLETA=desligada` in the user `.env` turns it off entirely (no queue writes, no uploads). The status page shows the state in one sentence.

### The receiver and the published dataset

The receiver is write-only: it has no route to read, list or download, and its source is not published to reduce the risk of leaking the collected data. Collected data will be periodically sanitized (names, paths, installation ids and anything identifying a person, client or project removed) and published in this repository; format, cadence and location will be announced here before the first publication. To request deletion, email `contato@mediumlatens.com` with the anonymous id shown on the status page.

## Português

### O que é registrado

Cada evento é um objeto JSON com horário, o identificador anônimo da instalação e um tipo. Os tipos que o servidor registra hoje:

| Tipo | Quando | Conteúdo |
|---|---|---|
| `turno_inicio` | um prompt é enviado | provedor, nome do modelo, o texto do prompt |
| `ferramenta` | o assistente chama uma ferramenta | id, nome e entrada da ferramenta |
| `ferramenta_fim` | uma ferramenta retorna | id, ok, resumo curto |
| `turno_fim` | o turno termina | ok, mensagem de erro se houver, tempo decorrido |
| `rota` | o painel chama uma rota do servidor | caminho e método (nunca o corpo) |
| `brief_generate`, `brief_markers` | o Brief Criativo roda | contagens e mensagem de erro se houver |

Uma vez por sessão, um resumo narrativo da sessão é gerado pela sua própria conta de IA, com o modelo mais barato dela, e entra na fila como qualquer outro evento.

### O que nunca é registrado

- **Credenciais.** Valores em formatos de provedores conhecidos (Anthropic, OpenAI, OpenRouter, ElevenLabs e Meta), chaves AWS, JWTs, tokens de Stripe, Google, npm, GitLab, Slack, DigitalOcean, Hugging Face e GitHub, blocos PEM, URLs de webhook, valores de variáveis de ambiente sensíveis e qualquer campo cujo nome pareça segredo são substituídos antes de o evento ser gravado. O texto passa primeiro por normalização Unicode. Uma heurística de aleatoriedade também remove valores de alta entropia com alternâncias repetidas entre maiúsculas e minúsculas e dígitos intercalados, depois redige fragmentos vizinhos de alta entropia. Isso roda em todo valor aninhado. Não é uma garantia absoluta: um segredo em formato desconhecido e composto somente por minúsculas pode passar. Veja [Limitações conhecidas](../SECURITY.md#known-limitations).
- **Bytes de mídia.** Buffers, typed arrays, base64 com assinatura de mídia, sequências longas de base64, dumps em hexadecimal e arrays numéricos de amostras são substituídos pelo marcador `[binario removido]`. Além disso, todo evento tem teto de 4096 bytes e todo campo de texto, 2048 bytes; um arquivo de mídia não cabe, seja qual for a codificação. Eventos truncados dizem quantos bytes foram descartados.

Essas proteções não têm interruptor. Estão testadas em `test/telemetria.test.js` e `test/telemetria-integracao.test.js`.

### A fila local

Os eventos são acrescentados a `telemetria/fila.jsonl` na sua pasta de usuário (`~/.medium-latens` no macOS, `%APPDATA%\Medium Latens` no Windows), modo 0600, no máximo 5000 linhas (as mais antigas são podadas). Nada é gravado antes do aceite dos termos na instalação. Você pode abrir o arquivo a qualquer momento.

### Envio

A cada cinco minutos, lotes de no máximo 200 linhas ou 1 MB são enviados por `POST` ao endereço de coleta (`https://coleta.torremaster.com/v1/eventos` por padrão) com três cabeçalhos: `x-instalacao` (o seu UUID anônimo), `x-medium-latens-app` (um identificador público fixo do aplicativo, filtro de ruído e não segredo) e `x-termos` (a versão dos termos que você aceitou). As linhas só saem da fila depois que o servidor confirma a contagem. Em falha, o cliente recua, dobrando o intervalo até 30 minutos. Se o receptor estiver fora do ar, a fila só acumula e é podada em 5000 linhas; nada se perde em silêncio, e a página de status mostra o último resultado.

### Obrigatória, ativa ou desligada

Os instaladores oficiais gravam um carimbo `BUILD` ao lado do `VERSION`. Com esse carimbo, a coleta é obrigatória e a variável de ambiente é ignorada; é isso que os termos descrevem. Um checkout do fonte não tem carimbo: a coleta vem ativa por padrão e `MEDIUM_LATENS_COLETA=desligada` no `.env` do usuário a desliga por inteiro (nada na fila, nenhum envio). A página de status mostra o estado numa frase.

### O receptor e o dataset publicado

O receptor é somente de escrita: não tem rota para ler, listar ou baixar, e o código dele não é publicado para reduzir o risco de vazamento dos dados coletados. Os dados coletados serão periodicamente higienizados (nomes, caminhos, identificadores de instalação e qualquer coisa que identifique pessoa, cliente ou projeto removidos) e publicados neste repositório; formato, periodicidade e local serão anunciados aqui antes da primeira publicação. Para pedir exclusão, escreva para `contato@mediumlatens.com` com o identificador anônimo que aparece na página de status.
